# Автономный разбор памяти

Отдельное задание launchd раз в час проверяет очередь. После 20 минут без изменений журналов Codex оно выбирает одну незавершённую сессию и запускает ограниченный разбор через `codex exec`. Тихий Stop сохраняется.

Опциональная [рефлексия существующих навыков](SKILL-REFLECTION.md) включается отдельно в конфиге памяти. Каталог обновляется до проверки пустой очереди/лимита модели. Исторические основания получают отдельный ограниченный reasoning-проход, когда обобщать сессии уже не требуется; его попытки входят в тот же суточный лимит. Нет оснований — нет дополнительного inference. Фон сохраняет только предложения, установка навыков выполняется отдельно.

## Ограничения

- До четырёх запусков модели за сутки UTC, включая неудачи. Один пакет на запуск. Пустая очередь и активный чат не расходуют запуск.
- Модель gpt-6.1-sol, effort low, таймаут 180 секунд. Пакет событий до 16 тысяч символов, входные данные до 40 тысяч плюс короткая инструкция. Это ограничения работы, не обещание определённой стоимости.
- Обобщение с сохранением прежнего состояния, обоснованные знания, темы и кандидаты процедур; сигналы повторения и аудит служат подсказками, не доказательством полезности.
- Фильтр include_projects действует и на ранее импортированные сессии. Форки не выбираются как независимые сессии.
- Подтверждённые решения, предпочтения, проверенные/закреплённые процедуры, действующие SKILL.md и измерения фон не изменяет. Установка навыка остаётся согласованным действием.

Модель получает очищенный пакет в изолированной временной конфигурации Codex: без пользовательских MCP/plugins/hooks, чтения AGENTS.md, shell, web, multi-agent и автоматической памяти; sandbox read-only. Обнаруженный вызов инструмента или неизвестное действие отвергает результат. Диагностические сообщения сохраняются отдельно. Временная конфигурация удаляется; ephemeral-запуск не попадает обратно в обычные журналы.

Используется существующий локальный вход Codex. Auth временно копируется с закрытыми правами, не попадает в репозиторий/отчёты и удаляется после запуска. Нормальное обновление токенов возвращается в исходный файл только при отсутствии параллельного изменения. Расход относится к настроенному аккаунту.

Модель возвращает кандидат JSON. Родительский процесс проверяет форму, типы изменений, точные цитаты, проект и версии; применяет штатным consolidate. Возобновление сессии или конфликт сводки блокируют применение. Пауза отменяет модельный subprocess. Общий lock исключает параллельные проходы, лимит учитывается до вызова модели.

## Управление

```sh
python3 background.py install
work-memory-background status
work-memory-background run --dry-run
work-memory-background pause
work-memory-background resume
work-memory-background uninstall
```

Установка допускает --model, --effort, --daily-limit, --codex. Она создаёт отдельный runtime, CLI и local.work-memory.curator.plist; определения hooks и прежний сборщик не меняются. Пауза сохраняется при переустановке. Удаление расписания сохраняет память и отчёты.

Явная ручная проверка выбранной сессии: `work-memory-background run --session SESSION_ID --allow-active`. Пропускается только проверка простоя; остальные ограничения остаются. Расписание этот флаг не использует.

На macOS нужна доступная пользовательская сессия и сеть. Спящий/выключенный компьютер не гарантирует запуск по времени; очередь ждёт следующей возможности. На Linux доступны ручные команды, установщик расписания пока только launchd.

## Результаты

В Obsidian: `Память/Фоновый разбор.md`. Под `~/.local/share/work-memory/background/`: runs — квитанции с usage, artifacts — кандидат JSON и предупреждения, config.json — лимиты. Основной конфиг памяти читается по исходному пути, включая новые фильтры проектов.

started не доказывает завершение. applied означает commit проверенного результата; pending_writes показывает незавершённую публикацию в vault. Проверка цитат не доказывает логическую правильность обобщения. Улучшение решений оценивается отдельными испытаниями процедур.

Основа запуска: [официальная документация codex exec](https://learn.chatgpt.com/docs/non-interactive-mode).
