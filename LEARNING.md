# Тематические знания и процедуры из опыта

Память ведёт два связанных слоя. **Тема** объясняет, что известно и почему: факты, решения, источники, связи, противоречия и срок проверки. **Процедура** описывает повторяемую работу: когда применять, шаги, ловушки и критерии результата. Процедура сначала имеет статус `candidate`; это не установленный навык.

Обобщение выполняет основной агент внутри обычного чата. Hooks доставляют контекст и напоминают о сохранении. Фонового процесса, дополнительных моделей, автоматического запуска команд из истории и обучения весов нет.

## Ежедневный цикл

1. `SessionStart` подбирает пропущенные журналы; `UserPromptSubmit` возвращает рабочее состояние, подходящие темы и процедуры с их оценкой.
2. Агент читает полную выбранную запись через `work-memory learning-show KEY`. Для новой задачи прежние сведения служат подсказкой; изменчивые факты проверяются заново.
3. После существенного результата `packet` предлагает поле `learning`. Агент обновляет существующую тему, связывает новые знания и при наличии переносимого опыта выделяет процедуру. Не каждый ответ становится новой записью.
4. При фактическом применении процедуры агент записывает `observe` с результатом `success`, `failure` или `unknown`. Просмотр инструкции не считается успешным применением.
5. Сравнение исходного способа и кандидата записывается отдельно как `trial`. Новая редакция имеет другую версию и не наследует результаты предыдущей.
6. `curate` показывает устаревшие сведения, новые снимки источников, явно отмеченные противоречия, похожие названия, неактивные ссылки и неудачи процедур. Решение об объединении или архивировании принимает человек/основной агент. Неиспользуемость сама по себе не причина удаления аварийной инструкции.

## Снимки источников

Для внешнего документа сначала сохраняется локальный текст, затем:

```sh
work-memory source-add --file /tmp/source.md --project my-project \
  --title 'Описание протокола' --origin 'https://example.org/protocol'
work-memory source-show SOURCE_ID
```

Команда не скачивает URL. Она хранит неизменяемый очищенный снимок в SQLite и выводит его в `Память/Источники`; секреты маскируются до сохранения. Изменённое содержимое получает новый ID. При новом снимке с тем же `origin` аудит сообщает, какие темы ещё ссылаются на старый. Изменение заметки человеком не меняет эталонный снимок в БД.

## Темы и кандидаты

Добавьте записи в `learning` обычного результата `packet` → `consolidate`:

```json
{
  "key": "delivery-diagnosis",
  "kind": "procedure",
  "project": "my-project",
  "title": "Проверка доставки событий",
  "body": "Проверять движение события от источника до результата.",
  "trigger": "При отсутствии ожидаемой доставки",
  "steps": ["Проверить свежую запись источника", "Проследить её до результата"],
  "pitfalls": ["Работающий процесс не доказывает доставку"],
  "checks": ["Найден результат для конкретной свежей записи"],
  "evidence": [{"event_id": "ID_СОБЫТИЯ", "quote": "ТОЧНАЯ ЦИТАТА"}],
  "links": [],
  "review_after": null,
  "base_revision": null
}
```

Для `kind: topic` вместо trigger/steps/pitfalls/checks используется `contradictions: []`. Основание может содержать `source_id` вместо `event_id`. Ссылки `links` ведут на ключи других тем/процедур и проверяются, включая область проекта. `review_after` — дата `YYYY-MM-DD`. Для изменения существующей записи нужен её текущий `revision` в `base_revision`; содержимое сначала читается через `learning-show`. Сам `packet` содержит только краткий каталог, чтобы не перегружать контекст.

Вики хранится в `Память/Темы`, `Память/Процедуры`; входная страница — `Память/Темы и процедуры.md`. Действуют тот же журнал файловых операций, восстановление после сбоя и защита ручных правок, что у основной памяти.

## Учёт применения и сравнения

```json
{
  "id": "delivery-use-001",
  "kind": "use",
  "key": "delivery-diagnosis",
  "revision": "ПОЛНАЯ_ВЕРСИЯ",
  "session_id": "ID_СЕССИИ",
  "outcome": "unknown",
  "note": "Процедура применена, downstream ещё не проверен.",
  "evidence": [{"event_id": "ID_СОБЫТИЯ", "quote": "ТОЧНАЯ ЦИТАТА РЕЗУЛЬТАТА"}]
}
```

Сохранить через `work-memory observe --input /tmp/observation.json`. Один ID нельзя позднее переписать; уточнение — новое наблюдение.

Для сравнения замените `kind/outcome` на:

```json
{
  "kind": "trial",
  "holdout": true,
  "baseline": {"success": true, "errors": 1, "seconds": 120},
  "candidate": {"success": true, "errors": 0, "seconds": 100}
}
```

Это иллюстрация формы, не данные реального испытания. Метрики должны быть измерены на сопоставимой задаче и подтверждены цитируемым отчётом. Отдельный runner и вызовы модели не запускаются. Система проверяет форму, ссылки и независимость сессий; она не доказывает достоверность измерений или сопоставимость задач. Оценка качества остаётся ответственностью основного агента и человека.

Правило `validated`: минимум две успешные проверки на независимых сессиях вне сессий создания/изменения процедуры, улучшение хотя бы одного показателя (успех, ошибки, время), без ухудшения успеха/числа ошибок. Повторения внутри одной сессии и форки не увеличивают число независимых проверок. Зафиксированная регрессия, неудача применения, некорректное основание или истёкший срок проверки дают `needs-review`. Это консервативный технический порог допуска, не статистическое доказательство превосходства.

## Согласованный навык

После проверки покажите человеку ключ, версию, процедуру и результаты. Согласие должно содержать ключ и первые 12 символов версии. Команда экспортирует пакет только для текущей `validated`-версии:

```sh
work-memory skill-export delivery-diagnosis --revision FULL_REVISION \
  --approval-event USER_EVENT_ID --approval-quote 'ТОЧНАЯ ЦИТАТА СОГЛАСИЯ' \
  --destination ~/.codex/skills
```

Проверяется наличие цитаты пользователя, ключа и версии, но не смысл согласия: отказ или обсуждение нельзя выдавать за разрешение. Выбор правильного основания остаётся обязанностью агента. В папке появляются `SKILL.md` и `references/provenance.json`; существующая папка никогда не перезаписывается. Альтернативный `--destination` позволяет сделать пакет для просмотра без установки. Изменение темы/кандидата не переписывает ранее экспортированный навык автоматически.

## Аудит, версии и восстановление

```sh
work-memory curate --project my-project
work-memory learning-show delivery-diagnosis
work-memory learning-manage delivery-diagnosis --action pin --revision REVISION
work-memory learning-manage delivery-diagnosis --action archive --revision REVISION
work-memory learning-manage delivery-diagnosis --action restore --revision REVISION
work-memory learning-rollback delivery-diagnosis --revision CURRENT --to-revision OLD
```

Закреплённая запись защищена от архивирования; сначала нужен явный `unpin`. Архивированные записи исключаются из поиска и рекомендаций, но не удаляются. История содержимого, результаты испытаний и журнал действий сохраняются. Откат восстанавливает старое содержимое; оценки соответствующей версии снова доступны, с повторной проверкой источников и сроков.

Служебные `<hook_prompt>` исключаются при импорте. Уже ошибочно импортированные сообщения сохраняют ID и текст для аудита, но получают роль `system`, исключаются из пакетов и не могут подтверждать пользовательское решение.
